Change-control print

docs-kit is change control for documentation — so its pages borrow the visual language of engineering drawings: cool paper, graphite ink, stamped verdicts, and a title block on every sheet. Colour is never decoration here — every hue names a layer, a lane, or a live state, and the bar below is that policy drawn to scale.

audience: developers light theme only zero JS · zero network single-file pages

§1Direction

  1. One metaphor, carried through. Every visual device is borrowed from drawing control: the amendment table is a revision block, the footer is a title block, decisions are stamped, diagrams sit on faint grid paper, and the pipeline is drawn as a line with stations. Nothing is decorated for its own sake.
  2. Hue is budgeted, and the budget is a rule you can see. Four families, no more: foundation blue, change violet, fast-lane teal, redline orange — plus verdict green/red, which live inside stamps and nowhere else. Roughly two thirds of every sheet stays graphite on paper; §2 draws that ratio to scale. Colour never carries meaning alone: completion is still geometry (hollow / half / filled dots), lanes are still pattern-coded, and hue is the second channel on top.
  3. The map's colors travel with the references. A hue is not decoration attached to a component — it names a layer. So the tracks' colors leave the diagram and follow every id, path, and card that points into that layer: blue sends you up to the stable Foundation, violet sends you across to the Change pipeline, orange means live right now. Scanning a page of tags tells you where the work will take you before you read a word.
  4. Type is inverted. Headings, ids, and labels are monospace — the ids are the protagonists of this system. Body prose is a quiet system sans. This is the opposite of the default docs look (sans display, mono details), and it is deliberate.
  5. Deterministic, identical everywhere. Tokens live inside the renderer; no per-project theming, no dark mode, no webfonts, no scripts. Same input docs → the same sheet, offline, in CI, on any machine.
  6. The signature is the map. Each page opens with its slice of one diagram family — the model drawn as transit lines: Foundation as three stations, the Change pipeline with the fast lane drawn as a literal bypass track, and the Decision→Architecture amendment edge in redline. No template produces this; it is the model's own topology.

§3Typography

Two roles, deliberately inverted. Display and labels: the system mono stack (SF Mono / Cascadia / Consolas — zero network, present everywhere). Body: the system sans. Numerals in tables are tabular by nature of the mono face.

Rules: anything machine-meaningful — ids, refs, paths, dates, counts, column headers — is mono. Prose links are ink with a 1.5px redline underline; chrome links (nav, TOC, tags) carry no underline.

§6The system map

The master diagram — the whole model as two lines. Foundation runs along the top; the Change line runs beneath it; the fast lane is a dashed bypass track around Proposal → Decision; and the only edge allowed to touch Layer 1 — a Decision amending Architecture — is drawn in redline. The index page opens with this exact figure:

Diagram rules: 2–2.5px tracks, each line owns its color · metro-style stations: 13px circles filled with the line color, white icon inside · dashed = bypass or tentative · redline dashed + chevron = the amendment edge (the only arrow on the map, because it is the only directional privilege in the model) · labels mono ink, captions as FIG lines. Graph nodes carry a 22px tinted icon badge (kind color) and edge labels sit in small chips so they stay readable on the grid paper.

Complex flows — layered graphs

When data_flow branches, the renderer stops chaining and draws the graph: nodes are placed in topological columns (longest-path layering, then a barycentre pass orders each column by the mean index of the nodes it points at — Sugiyama's own heuristic, fully deterministic, no layout engine), edges are drawn with the same ink strokes and chevrons. Fan-out, fan-in, and async hops all read at a glance:

Flow syntax the renderer parses (one edge per line in data_flow): a -> b sync · a ~> b async (drawn teal, dashed) · a -> b : label edge label. Node kind comes from an optional annotation on the components entry — postgres [db], jobs [queue], dashboard [ui] — which sets the icon and tint; unannotated components are services, and any node not listed in components at all is automatically drawn dashed as an external system. Scale rule: there is one presentation, the graph, at every density — the split-by-flow-group style was removed in 0.9.1 and nothing replaced it. The budgets (20 nodes · 32 edges · 10 rows) decide only whether to print a warning note suggesting the flow be split across Architecture docs; the figure is always drawn at natural size and scrolls inside its own frame, because a figure is never scaled below natural size. A data_flow the renderer cannot parse falls back to the markdown body verbatim — it never guesses a diagram.

Logic and structure — four more fences

A graph of data_flow answers where does data go. Four other questions get four other fences, all through the same engine — adding a type is one name in FIGURE_FENCES and one parser, never a second layout engine.

fenceanswersnotation
flowchartwhat happens when — where does this branch◇ branch point · ▭ step · ⬭ entry/exit
statewhat an entity's life looks likerounded state · blue border = initial · double border = final
erdwhat the data is shaped likecrow's foot = many · bar = exactly one · ○ = optional
classwhat the code's contracts arehollow triangle = extends/implements · dashed = implements

One source per fact. erd and class have no relationship syntax at all: an fk -> t.c flag is the relationship and its cardinality follows from what a foreign key means, and a field whose type names another declared type is the association. Nothing is written twice, so the picture cannot disagree with the table beside it.

Weight is the reader's way in. A flowchart exists to answer one question — where does this branch — so the diamond is deliberately the heaviest object on the page: 2px stroke, --l1-wash fill. A step drops to 1.25px graphite and reads as ground. The two ends stop being identical capsules: the entry keeps full-weight ink, the exit is drawn light. No new hue is spent — L1 was already the diamond's colour.

A relation is not a flow

An edge in data_flow means data moving. A foreign key does not travel, and neither does a generalization. Drawing them with the flow curve said the wrong thing twice over: it started nowhere in particular, and the middle of a tall entity box is a column that has nothing to do with the key being drawn. erd and class therefore route as structure, which is paint and not layout — layering, the feedback arc set and the return lanes are the same code either way.

relationleaves fromlands on
erd · foreign keythe fk column's own rowthe row it names
class · field of a declared typethat field's own rowthe target's header band
class · extends / implementsthe header band — it belongs to the type, not to any memberthe target's header band

One relation is one line, from its own row to its own arrowhead, in a vertical lane of its own. Nothing is shared, so tracing a line backwards can only end in one box. The single exception is a measurement rather than a preference: two arrowheads fit inside a 26px header band and three foreign keys into a 20px primary-key column do not, so only below that threshold do they converge on a trunk with junction dots — every tail still carrying its own marker on its own row. A converged trunk wears the symbol most of its members carry, and the minority fact — a lone nullable key's ○ — is left to the null flag in the table beside it.

An arrowhead's tip lands on the target's border. Every marker puts its tip on the path's own end point, so a standoff constant in the router stood every arrowhead in every figure short of what it pointed at. There is no standoff constant. markerUnits defaults to strokeWidth, so a marker's real size is markerWidth ÷ viewBox × stroke-width — the crow's foot and the UML triangle are matched to the other markers by ink, not by box, because the foot's toes span 11 of its 12 viewBox units while the chevron spans 7 of 10.

Two coincidences are asserted away. No two relations leave one header band at the same y — the dashed one would paint over the solid one. No two feeders reach a trunk from opposite sides at the same y — that draws one unbroken line straight through the junction, which reads as "these two connect to each other". And no segment is shorter than 24px, because a shorter one is eaten by its own arrowhead and what is left is a tick, not a line. Verify geometry by walking the segments actually emitted: a crossing counter is blind to overlap, to T-touches, to floating ends and to runs too short for their own head.

The table under a figure

Every figure ships a table, and it is never a rescue: it is the exact wording, the copyable record, and the figure's accessible reading. No row is ever dropped to make a figure look better. What was dropped is repetition — the leading name becomes a band printed once, two vertical hairlines cut each row into what it is, what it is specified as and what it means, and an empty cell becomes a faint dot so it stops competing with real text. A flowchart used to carry two tables that between them never answered at this branch point, how many ways out and where does each go; it now carries one decision table banded by source, and a state machine uses the same shape with the state and its meaning in the band.

This is also why the class figure may draw a method as name(…): the full signature has a column of its own below. Printing it in the box put the same 46 characters on the page once per implementer, which drove the canvas past CONTENT_W and clipped the right-hand column.

§9Motion & access

motiononly meaning-bearing motion, all pure CSS (still zero JS), three moves total: packet — a white light gliding along solid edges shows data direction (2.4s cycle); marching dashes — dashed strokes (async, fast-lane, amendment) drift toward their target (slow, 16s); LED pulse — a soft ring on live dots: orange = in-progress, green = docs-check clean (2.2s). Nothing animates on entrance or hover, and prefers-reduced-motion kills every animation (packets hide entirely)
colorfive places, all rule-driven, none decorative: the section tab (3px, the hue that section spends) · tags (destination layer, §2) · washes behind stamps, deviation notes, lane tags, the active TOC row and hovered table rows · gradients on tracks only — each line deepens toward its terminus, so the drawing reads as drawn with pressure · the highlighter, the redline pen laid flat, reserved for the one operative sentence in a section — three marks on this whole sheet
focus2px redline :focus-visible outline on every link, tab, and summary
contrastbody ≥ 7:1; every deep step clears AAA on paper and AA on its own wash (blue 9.3, violet 8.0, teal 7.0, redline 6.5); verdict inks ≥ 4.5 on their stamp fill. Teal is a mid-tone — small text on the raw line step takes graphite, not white. Statuses never rely on hue alone: the dot shape carries the meaning and the lanes stay pattern-coded
responsivesidebar folds above content < 960px; boards and the title block reflow; SVG maps scale full-width
